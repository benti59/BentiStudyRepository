# 贡献指南

## 欢迎贡献！

感谢您对本知识库的兴趣！我们欢迎任何形式的贡献，包括但不限于纠正错误、补充内容、优化结构或翻译文档。

## 贡献方式

### 1. 报告问题 (Issues)
如果您发现以下问题，请通过 Issues 页面报告：
- 文档中的技术错误或笔误
- 内容缺失或不完整
- 结构不合理或难以理解
- 图片、链接等资源失效
- 任何改进建议

**报告问题格式：**
- **标题**：简洁明了地描述问题
- **内容**：
  - 问题描述
  - 相关文件路径
  - 期望的修正方式
  - 其他相关信息

### 2. 提交拉取请求 (Pull Requests)
如果您希望直接修正问题或添加内容，请提交 Pull Request：

#### 步骤：
1. **Fork 本仓库**
2. **创建新分支**：
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. **进行修改**并提交：
   ```bash
   git commit -m "类型: 简要描述"
   ```
   **提交信息规范**：
   - `docs:` 文档更新或添加
   - `fix:` 修复错误
   - `feat:` 新功能或内容
   - `style:` 格式调整
   - `refactor:` 重构
   - `chore:` 维护性任务

4. **推送到您的分支**：
   ```bash
   git push origin feature/your-feature-name
   ```

5. **创建 Pull Request**：
   - 描述您的修改内容和原因
   - 关联相关 Issue（如有）
   - 等待代码审查

## 内容规范

### 文档标准
1. **文件格式**：使用 Markdown (.md) 格式
2. **编码**：UTF-8
3. **命名规范**：
   - 使用中文或英文，保持一致性
   - 使用连字符分隔单词
   - 避免特殊字符和空格

4. **内容质量**：
   - 确保技术准确性
   - 逻辑清晰，层次分明
   - 示例代码应可运行
   - 图片需清晰，并配有描述

### 目录结构
请遵循现有目录结构：
- 按科目分类
- 每个科目下有独立的 README.md
- 图片资源放在对应科目的子目录中

## 翻译指南

如果您想帮助翻译文档：

1. **中英对应**：确保翻译版本与原始版本内容一致
2. **术语统一**：使用标准技术术语翻译
3. **文化适应**：适当调整示例以符合目标语言环境
4. **保持更新**：当原文更新时，请同步更新翻译

## 行为准则

我们承诺为所有人提供一个友好、尊重和无骚扰的环境。请遵守以下准则：

1. **尊重他人**：保持专业和礼貌的交流
2. **建设性反馈**：提供具体、有帮助的建议
3. **包容性**：欢迎不同背景和经验的贡献者
4. **耐心沟通**：理解他人可能有不同的视角

## 许可证

所有贡献都将根据项目的 [CC0 许可证](LICENSE) 进行授权。提交贡献即表示您同意您的贡献将在此许可证下发布。

## 致谢

所有贡献者的名字将被记录在项目的 [贡献者列表](CONTRIBUTORS.md) 中（待创建）。

# Contributing Guidelines (English Version)

## Welcome Contributors!

Thank you for your interest in this knowledge repository! We welcome contributions of all kinds, including but not limited to fixing errors, adding content, improving structure, or translating documentation.

## Ways to Contribute

### 1. Reporting Issues
If you find any of the following issues, please report them via the Issues page:
- Technical errors or typos in documentation
- Missing or incomplete content
- Unreasonable structure or difficult to understand
- Broken images, links, or other resources
- Any suggestions for improvement

**Issue Reporting Format:**
- **Title**: Concise description of the issue
- **Content**:
  - Problem description
  - Relevant file path
  - Expected correction method
  - Other relevant information

### 2. Submitting Pull Requests
If you wish to fix issues or add content directly, please submit a Pull Request:

#### Steps:
1. **Fork this repository**
2. **Create a new branch**:
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. **Make changes** and commit:
   ```bash
   git commit -m "type: brief description"
   ```
   **Commit Message Conventions**:
   - `docs:` Documentation updates or additions
   - `fix:` Bug fixes
   - `feat:` New features or content
   - `style:` Formatting changes
   - `refactor:` Code refactoring
   - `chore:` Maintenance tasks

4. **Push to your branch**:
   ```bash
   git push origin feature/your-feature-name
   ```

5. **Create a Pull Request**:
   - Describe your changes and reasons
   - Reference related Issues (if any)
   - Wait for code review

## Content Standards

### Documentation Standards
1. **File Format**: Use Markdown (.md) format
2. **Encoding**: UTF-8
3. **Naming Conventions**:
   - Use Chinese or English, maintain consistency
   - Use hyphens to separate words
   - Avoid special characters and spaces

4. **Content Quality**:
   - Ensure technical accuracy
   - Clear logic and well-structured hierarchy
   - Example code should be runnable
   - Images should be clear with descriptions

### Directory Structure
Please follow the existing directory structure:
- Categorized by subject
- Each subject has its own README.md
- Image resources placed in corresponding subject subdirectories

## Translation Guidelines

If you would like to help translate documentation:

1. **Consistency**: Ensure translated versions match the original content
2. **Terminology**: Use standard technical term translations
3. **Cultural Adaptation**: Adjust examples appropriately for the target language environment
4. **Keep Updated**: Please update translations when the original is updated

## Code of Conduct

We are committed to providing a friendly, respectful, and harassment-free environment for everyone. Please adhere to the following guidelines:

1. **Respect Others**: Maintain professional and polite communication
2. **Constructive Feedback**: Provide specific, helpful suggestions
3. **Inclusivity**: Welcome contributors from diverse backgrounds and experiences
4. **Patient Communication**: Understand others may have different perspectives

## Acknowledgments

All contributors' names will be recorded in the project's [Contributors List](CONTRIBUTORS.md) (to be created).
